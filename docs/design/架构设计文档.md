## 1. 系统架构概述

### 1.1 项目背景

后端接口迁移平台是为了解决接口从旧版本迁移到新版本时的稳定性问题。通过渐进式迁移、灰度验证、并行对比等机制，确保迁移过程安全可控。

### 1.2 设计目标

- **渐进式迁移**：通过7个阶段逐步切换，降低单次切换风险
- **灰度验证**：支持按百分比，黑名单、白名单、表达式等方式进行灰度
- **平滑切换**：支持向前按顺序切换，向后任意切换
- **可观测性**：自动进行Diff对比，记录差异结果

## 4. 状态机设计

### 4.1 状态定义

7个迁移阶段：

| 阶段 | 状态码 | 说明 |
|------|--------|------|
| OLD | 1 | 单调用旧接口 |
| VALIDATION_GRAY | 2 | 验证-灰度：新旧接口并发，Diff验证，返回旧接口结果 |
| VALIDATION_ALL | 3 | 验证-全开：新旧接口并发，Diff验证，返回旧接口结果 |
| GO_LIVE_GRAY | 4 | 上线-灰度：新旧接口并发，Diff验证，根据灰度规则返回 |
| GO_LIVE_ALL | 5 | 上线-全开：新旧接口并发，Diff验证，返回新接口结果 |
| DECOMMISSIONING_GRAY | 6 | 停用-灰度：根据灰度规则调用，Diff验证 |
| DECOMMISSIONING_ALL | 7 | 停用-全开：只调用新接口 |

### 4.2 状态流转

```
向前切换（升级）：必须按顺序  1→2→3→4→5→6→7
向后切换（降级）：任意跳转    7→1, 7→3, 5→2 等
```

## 5. 配置中心设计

### 5.1 配置key命名空间

| 类型 | key格式 | 说明 |
|------|---------|------|
| 迁移配置 | migration_{key} | 迁移任务基础配置 |
| 灰度规则 | migration_{key} | 灰度规则列表 |
| Diff规则 | migration_{key} | Diff规则列表 |

### 5.2 配置存储说明

- 迁移配置、灰度规则、Diff规则存储在配置中心
- Diff结果存储在数据库，供后续查询和统计分析
